# 护栏3 · 需求置信度上报（Confidence Gate）

## 规则
- 对每个需求条目评估置信度。**看不懂 / 低置信（low / none）的需求项，不生成对应代码**。
- 把看不懂的项列成 `pending_requirements` 反馈给用户确认，**不替用户私自拍板**。
- 高置信部分可以先做；两种顺序皆可：先做完高置信再反馈低置信，或边做边挂起低置信。

## 禁止
- 禁止在需求模糊时空想一个实现硬写下去。
- 禁止「我猜用户是这个意思」式自由发挥。
- 禁止默默替用户决定需求口径。

## 产出
向用户提交 `pending_requirements`：
- `req_id`: 回指需求
- `confidence`: low / none
- `reason`: 为什么看不懂 / 歧义点
- `code_generated`: false（此类不生成代码）

## 边界
- 全部需求低置信 → 仅产出 pending_requirements，不生成任何代码，请用户补充需求。
- 部分低置信 → 高置信部分仍可报完成，低置信部分挂起待确认。
